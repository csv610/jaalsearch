================================================================================
ARCHITECTURE IMPROVEMENTS
================================================================================

BEFORE Refactoring:
├─ CLI and Streamlit apps had duplicate search logic
├─ No unified interface across search engines
├─ Error handling scattered across multiple files
├─ Hard to add new search engines
├─ Mixing business logic with UI code
├─ Difficult to test search functionality
└─ Code reuse impossible

AFTER Refactoring:
├─ All search logic in one module (search_engines.py)
├─ Unified interface via SearchEngine ABC
├─ Consistent error handling in one place
├─ Easy to add new search engines (just extend base class)
├─ Clean separation of concerns
├─ Easy to unit test search classes
├─ Fully reusable across applications

================================================================================
DESIGN PATTERNS APPLIED
================================================================================

1. Abstract Base Class (ABC)
   - Defines contract that all search engines must follow
   - Ensures consistent interface

2. Factory Pattern
   - Creating search engine instances in applications
   - Decouples object creation from usage

3. Dependency Injection
   - API keys and configuration passed via constructor or environment variables
   - Flexible configuration management

4. Caching
   - Streamlit: @st.cache_resource for expensive object creation
   - Method: @functools.lru_cache for Wikipedia summary caching

5. Single Responsibility
   - Each class focuses on one search engine
   - UI code focused on presentation only
